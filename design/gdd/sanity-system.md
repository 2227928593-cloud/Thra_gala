# 理智系统与周目锁拆除 · 设计方案

**版本** v0.9（待主理人审 → 用户拍板）· 设计：文策渊（design-strategist）
**范围** 本轮只出方案。**不改** `js/`、`tests/`、`art/`。
**上游** `js/data.js` `js/story2.js` `js/story3.js` `js/story4.js`（103 节点）、`js/engine.js`（`DIFFICULTY` / `check()` / `forcedTarget()`）、`design/gdd/difficulty-redesign.md`（§12 终值）
**诉求（用户原话）**：「有的选项是"通关才能选择"，这些选项不要了；再加一个理智值，玩家的选择会影响理智值，一些通关必要选项或重要线索的选项要一定理智值才能出现。」

---

## 0. 摘要

1. **周目锁只有 2 处，全拆**。`p5:3` 直接删（它的文案本身就是"你记得上一次"，救不回来）；`d1:4` **改成线索锁**（`no_basement`）——它原本说的是"你知道这面墙上没有门"，其实完全可以由"这栋楼没有地下室"这条**局内知识**支撑，不必靠记忆。这样保留了好句子，又不再有"通关才可选"。
2. **连带一条必须处理**：`m_second_time`（档案「第二次的门」）的唯一授予点就是这两处周目内容。**不能直接删**（会触发 `validate.js` 的"档案永远无法解锁"，且档案数 42 被测试守着）。建议把它改挂到新的**理智断片**节点上——"你回到了同一个夜里"这句话，放在"你精神断片后重新睁眼"上比放在"你玩过一遍"上更成立。
3. **理智（`sanity`）与 `corruption` 的正交不是靠数值区分，是靠方向区分**：
   - `corruption` 涨在**"动手"**（碰鬼、咬眼、借力）——身体被吃；
   - `sanity` 掉在**"看懂"**（看见不该看的、听见、想通不该想通的）——头脑被撑裂。
   所以"看"扣理智、"摸"扣复苏，两条账永远不在同一个动作上收钱。
4. **理智不锁"通过"，只锁"看得清楚"**。我把它做成**降级而非消失**：理智不足时，精确、干净的做法消失，取而代之的是一个**代价更高的粗暴版本**。玩家永远能过，但过得更难看、更贵。这条同时满足用户"必要选项要一定理智"的诉求和"不能软锁"的硬约束。
5. **理智 0 不死**。强制进入 `sanityBreak`（断片）：黑屏 → **回到刚才那一步**（触发断片的节点）→ `clock +30`、理智恢复到 40。代价是时间，不是命——和本作"时间是最贵的资源"一致。

## 2. 任务 A：拆掉周目锁

### 2.1 两个选项：一个删、一个改线索锁（推荐 A2）

| 选项 | 建议 | 理由 |
|---|---|---|
| `p5:3`「你记得听完之后，它就开始找你了。」 | **删除** | 它的信息量就是"我记得上一次"，没有任何局内依据可以替换。保留它必然要发明一个"你怎么知道的"来源，等于换个方式做周目奖励。删掉后 `p5` 剩「点开」/「不点」两项，反而更干净。 |
| `d1:4`「别摸了。门不在这里——它在等你开门。」 | **改条件**为 `when:{clue:'no_basement'}`，`lockedHint:'这栋楼到底几层，我还没数清'` | 这句话的内容（"这面墙上没有门，因为根本没有地下室"）完全可以由**局内知识**支撑：`act3:1`「停下来，喊住所有人」或 `c2/o_floor`「楼层标识」都会给 `no_basement`。于是它从"通关才可选"变成"看懂了才可选"——和全篇其它门槛同一套语法，且保住了一句好台词。 |

> 备选 A1（如果你想更彻底）：`d1:4` 也直接删。代价是 `d1` 少一个"我已经知道了"的选项，但**不损失任何路径**——`d1` 还有「摸黑找门」/「顺着水声走」/「打开手机灯」三条出口。

### 2.2 四处旁白：全删（推荐），并说明为什么不是"保留但改条件"

这四句的共同点是**直接断言 meta 记忆**（"你又躺回同一张床"、"上一次你也是站在这里数的"）。用户要的不是"少一点周目味"，而是**不要通关才有的内容**。把这四句改成 `when:{flag:'xxx'}` 换个旗标，只是把"通关解锁"改名成"某事件解锁"，仍然是二周目福利。

- 删掉后 `act1` 的开场是干净的第一次：`六月二十日，夜里十点十分。` → `你叫杨间……` → `屏幕的光把你的脸照得发青。`
- `f10` 那两句删掉后，剩下：`如果什么都不做，五点三十分，所有人都会死。` → `你只有一次机会。` → `你数过。` 这句**不是**周目台词，是"数眼睛"的当下动作，保留。

> 如果用户希望保留一丝"轮回感"，正确的做法不是旁白，而是**理智断片时的一句既视感**（见 §3.9）——它属于角色当下的精神状态，不属于玩家的存档历史。

### 2.3 `flag 'ng'` 与 `cycle`

- 数据侧：拆完后**零引用**。可以保留 `startNew` 里写 `ng` 的三行（无害），也可以顺手删掉——**建议保留**，因为将来若做"续卷"可能需要区分周目，而它现在不产生任何内容差异。
- `cycle`：只影响结局页那行「第 N 次走进这一夜」。**不动**，除非用户要求连这行统计也去掉（见 §4 Q4）。

### 2.4 连带：`m_second_time`（档案「第二次的门」）怎么办 ⚠️

这是本轮**最容易漏的一颗雷**：`m_second_time` 全篇只有两个授予点，就是 `data.js:155` 和 `p5:3`——也就是这次要删的两处。删掉后：

- `tools/validate.js` 会立刻报 `档案永远无法解锁（没有任何授予点）: m_second_time`；
- README 与 `tests` 里的「42 条档案」会被牵动（档案数没变，但校验红）。

**推荐**：把 `m_second_time` 改挂到新的 **`sanityBreak`（断片）节点**上。

理由：这条档案的原文是「你回到了同一个夜里。床、充电线、屏幕上那个标题很朴素的帖子，全都在原位。你知道录音里有什么……但这一次，你至少可以先低头，看看自己的手。」

这段话在"我玩过一遍"的语境里是元叙事；在"**你在厕所地板上断片，再睁眼时回到了这一段的开头**"的语境里，它是**角色的既视感**——更吓人，也更贴合。授予点从"通关奖励"变成"精神断片的后果"，正好是本轮要的方向。

> 备选：删掉这条档案，档案数 42 → 41，同时改 README 与测试里的数字。**不推荐**——为删一句话去动被测试守着的计数，收益不匹配。

## 3. 任务 B：理智系统

### 3.1 定位：与 `corruption` 正交（从"方向"上分开，不从数值上分开）

两条账的分界线不是"谁涨得快"，而是**钱从哪个动作上收**：

| | `corruption`（复苏） | `sanity`（理智） |
|---|---|---|
| 一句话 | 身体被鬼吃掉 | 头脑还清不清楚 |
| 收钱动作 | **动手**：碰鬼、睁眼、咬眼、借力、摸树 | **看懂**：看见、听见、想通、丢下人、通宵 |
| 典型来源 | `d6 +8`、`e7 +18`、`d7b +16`、`f10 +25` | `d5 −8`、`e7 −15`、`f2 听下去 −10`、`f10 咬眼 −20` |
| 高了的后果 | 变强（免电看暗处）→ 走向 `e_absorb` | 变糊涂（选项降级、观察失真、出现幻觉选项）→ 走向断片 |
| 恢复手段 | 掐伤口 / 念名字 / 周正忠告 | 想通规则 / 坐下想清楚 / 屏息成功 / 扶起一个人 / 看"数得清的东西" |
| 是否致死 | 是（幕末 `brk` → `end_absorb`） | **否**（0 只断片，回刚才那一步 / +30 分） |

**设计上的一句话**：`corruption` 是**你付出了什么**，`sanity` 是**你还剩多少自己**。

> 一个刻意的错位：`f10`「咬下那只眼睛」同时 **`corruption +25`（身体）** 和 **`sanity −20`（头脑）**。这是全篇唯一一处两条账一起收的地方，因为"吃自己的眼睛"既是身体事件也是精神事件。它也是全篇最贵的一步——值得。

### 3.2 范围与初值与三档参数

| 项 | 故事 | 标准 | 噩梦 |
|---|---|---|---|
| 初值 | **100** | **100** | **100** |
| 范围 | 0–100（写入即夹，同 `battery`） | 同 | 同 |
| **扣减系数** | **×0.5**（向下取整，最小 1） | **×1.0** | **×1.25**（向上取整） |
| **恢复系数** | **×1.5** | **×1.0** | **×1.0** |
| 0 点行为 | 不触发断片，只加一段旁白，理智锁在 1 | 触发一次断片 | 触发一次断片，恢复 30（不是 40） |

> 为什么初值都是 100：理智的"起点"必须一致，三档差异放在**衰减/恢复系数**与**是否锁选项**上。这样同一段剧情在三档里读起来是同一个人，只是"扛不扛得住"不同。

### 3.3 显示方式：两个方案

#### 方案 A · 显式（数值 + 条）

HUD 上加一条与「复苏」并列的「理智」条，或在档案页给精确数值。

- **优点**：可规划。玩家能算"我还能看几处"，与 `battery`/`knock` 的管理手感一致。
- **缺点**：HUD 已经有 5 个读数（时刻/电量/敲门/鬼眼/复苏）。再加一条，这一夜就变成仪表盘了。而且**理智值一旦可见，"发疯"就变成了"血条快空了"**——恐怖感直接归零。

#### 方案 B · 隐性（只有文本与表现）

不显示任何数字或条。玩家只能从这些地方推断：

- **呼吸声**：环境音里多一层自己的呼吸，越接近崩解越响、越不齐；
- **画面**：边缘开始轻微横向抖动（`.dazed` 类，CSS 可做），不影响可读性；
- **文本**：旁白开始出现**错字**（"杨间"→"杨间间"）、**错误归属**（张伟的台词挂到"老人"名下）、**重复句**；
- **选项**：措辞变形（"抓住段鹏的手"→"抓住……谁的手？"），以及**幻觉选项**出现。

- **优点**：这是唯一能让"发疯"真的吓到人的做法；也让玩家像角色一样**不知道自己还剩多少**。
- **缺点**：不可规划。玩家可能在毫无预警的情况下丢掉关键选项，产生"游戏坑我"的观感。

#### 推荐：**B+（隐性为主 + 一个可查的地方）**

> **剧情里不显示，档案里可查。**

- HUD 上**没有**理智条、没有数字；
- 但**档案页（codex）顶部**始终显示当前档位名：`清醒 / 动摇 / 恍惚 / 错乱`——四档文字，不显示数值；
- 跨档时给一次**只发生一次**的可读提示（呼吸变调 + 一行旁白），不弹 toast、不闪红。

为什么推荐 B+：

1. 它保住了"发疯"的恐怖（HUD 上没有进度条）；
2. 它解决了 B 的不公平——**想清楚的玩家随时可以打开档案确认自己在第几档**，像翻自己的笔记；
3. 档案页是这个游戏已有的"玩家主动查阅"界面（档案/线索/结局都在这），把理智档位放进去，语义是"你对自己状态的判断"，不是"系统给你的数值"。

| `plain` 级（氛围） | `o_badge`、`o_window`… | **−1** | 微量的"多想了一层" |
| **冲击点**（单列） | `c2a/o_zhao` 赵强 −4 · `d7/t_skins` 人皮 −4 · `f10/o_f10_faces` 同学的脸 −5 · `act4/z_belly` 肚子 −3 | — | 这几处是全篇最不该盯着看的东西 |
| **锚点（恢复）** | `d1/o_sink` 水龙头 **+4** · `act5/o_pl_watch` 表 **+3** · `f9/o_gate_steps` 地砖 **+4** · `g5/o_end_phone` 卫星电话 **+3** · `c2/o_floor` 楼层标识 **+2** | — | 水滴、表、地砖、一台机器的屏幕——**有刻度、能数、有因果** |

**每幕上限**：同一幕内，"扣理智的观察"最多生效 **3 次**（`flags.__sanobs_<act>` 计数）。第 4 次起只给文本、不给数值。

- 这条是为了防止"敢看的人被自己的好奇心杀死"，也防止"观察系统"和"理智系统"互相抵消（见 §3.12）。
- 恢复类观察不受此限。

### 3.7 不能软锁：逐条证明（硬约束）

**结构性保证（先立三条不变量）**

- **I1 · key 级观察点永不参与理智判定。** 所有 `hotspotTier()==='key'` 的点（即被任何 `when` 消费的线索的来源）理智消耗恒为 0，也不受"每幕 3 次"上限影响。→ 真结局依赖的 `saw_sixth / eye_rule / ghost_domain` 观察来源永远可拿。
- **I2 · 任何被理智锁住的"必通"，必须同时存在一个不受理智约束的入口。** 目前只有 B1 / B2 两处，见下表。
- **I3 · 幻觉选项只增不减。** 低理智永远**多**给选项，不会把选项表清空。

| 必通项 | 它为什么必通 | 低理智下的替代路径 | 替代路径是否受理智约束 | 结论 |
|---|---|---|---|---|

### 3.9 失败状态：理智 0（两个方案，推荐甲）

#### 甲「断片」（推荐）

```
sanity <= 0 且本幕未断片过
   → 强制进入 sanityBreak（新节点）
   → 黑屏 3 秒（fx:'black'）+ 一句旁白
   → route 回「刚才那一步」= 触发断片的那个节点（复用 k13 的 __k13_back 思路）
   → 结算：clock +30、sanity = 40、授予档案 m_second_time
   → 本幕不再触发第二次（flags.__broke_<幕>）
```

- **回的是「刚才那一步」，不是「本场景开头」。** 这两者差得很远：如果 `e7` 断片退回场景开头（`e5`），玩家要重看 `e5 → e6 → e7` 三段，真实代价变成 `30 + 3×6 = 48 分`；而标准档零观察路线到 `f10` 只剩 **44 分**余量——**一次中后段断片就足以把时间推过 05:30**，触发报时与强制 `f10`。那和"断片只罚 30 分"的定价完全不符，玩家的感受会是"回档 bug"而不是"我疯了"。
  —— 台词本来写的就是「我回到了**刚才那一格台阶**」「刚才那一段，像被人从中间剪掉了一截」。**行为和文案必须对齐**，这一条是验收项 R1 的直接来源。
- **代价是时间**：`+30 分`，**不重走已经看过的节点**。在 22:10→05:30 的预算里，一次断片等于吃掉 5 处观察——这个价签和「看了 5 处不该看的东西」正好对称。
- **实现契约（缺一条就会翻倍或错位）**：
  1. **回跳必须 `noCharge + skipEnter`**：否则回到被打断的节点时会重复扣一次节点耗时、并把它的 `enter` 再结算一遍。`k13` 的回归在同一个坑上踩过，这里用同一套写法。
  2. **`sanityBreak.enter` 只做 `codex: ['m_second_time']`**，**不要**再写 `clock +30` / `sanity = 40`——引擎在转场之前已经结算过，节点里再写一遍就是双倍。
  3. `m_second_time` 由 `addCodex` 去重，反复断片不会重复授予；档案数恒为 42。
  4. 引擎写 `__sanity_back` 时必须写**触发断片的那个节点 id**，不能写 `ck.node`（场景开头）或 `actStart`（幕首）。
- **不做的事**：不掉同伴、不掉线索、不掉道具。理智是"你自己的问题"，不该惩罚队伍。

#### 乙「幻听主导」

不打断流程：理智锁在 1，接下来 3 个节点强制走"幻觉版本"（每步 `clock +10`、`knock +2`），幕末恢复到 45。

- **优点**：不打断节奏，更像"你带着幻觉继续走"。
- **缺点**：连续 3 个节点失去控制权，比一次黑屏更让玩家烦；且"幻觉版本"要为每处单独写文案，成本高。

> 我推荐**甲**：它是确定性的、可预算的、复用了已有回滚语义，而且黑屏 3 秒本身就是一次很好的惊吓。

### 3.12 与观察系统的关系（"看清"vs"承受"）

观察与理智天然打架：观察是唯一的认知来源，理智会被"看见"惩罚。三条规则把这个冲突限住：

1. **I1：key 级观察点永不扣理智。** 玩家"为了通关必须看的东西"不会让他疯。这条同时是反软锁的结构保证。
2. **每幕 3 次上限。** 一幕里最多被扣 3 次（约 −6 到 −12）。它把"敢看"的成本封顶，玩家不会因为好奇而在第一幕就把自己看崩。
3. **恢复点里有一半是"看具体的东西"**（水滴、表、地砖、卫星电话）。于是观察系统里出现了一个**可学习的分支**：
   - 看**不可名状**的东西 → 掉理智（但拿线索）；
   - 看**数得清**的东西 → 回理智（多数也给线索）。

> 这条规则的价值不只是平衡，它是**主题**：在这个世界里，能救你的不是"更懂鬼"，而是"还记得水龙头没关紧"。

#### 档位门槛的写法陷阱（`f8:1` 为什么不能用 `diff`）

直觉写法是：

```js
when: { diff: 'nightmare', minSanity: 30 }   // ❌ 会出事
```

但引擎的 `check()` 里 `diff` 是**合取**的——`cond.diff` 不匹配当前档位就直接返回 false。所以上面这行读作「**只**在噩梦档存在」，而不是「噩梦档额外要求理智」。实测（`?node=f8&diff=standard`）：

| 档位 | 理智 | 直觉写法 | 正确写法 |
|---|---|---|---|
| 故事 | 100 / 20 | **两个都被锁** ❌ | 都可用 ✅ |
| 标准 | 100 / 20 | **两个都被锁** ❌ → `e_written` 直接不可达 | 都可用 ✅ |
| 噩梦 | 100 | 可用 | 可用 |
| 噩梦 | 20 | 被锁（理智） | 被锁（理智） |

**最终写法**（数据侧用函数条件，`check()` 原生支持 `typeof cond === 'function'`）：

```js
{ text: '再打一次。让他把纸丢下。', next: 'f9',
  when: s => !(s.difficulty === 'nightmare' && (s.stats.sanity == null ? 100 : s.stats.sanity) < 30),
  effects: { flags: { got_paper: true }, items: { paper: 1 }, ... } }
```

三重保障：

1. **故事/标准档完全不受理智影响**（`s.difficulty !== 'nightmare'` 直接为真）→ `e_written` 在任何理智下都可达；
2. **噩梦档才要求理智 ≥30** → 专家模式把"拿到纸"变成需要保持清醒的挑战；
3. **提示文案天然正确**：函数条件不会被 `sanityGateFailed()` 识别，于是落到 `lockedHintFor()` 的兜底——噩梦档的兜底正好是"你连这一步都想不清了"。

> 如果将来要用 `when.diff` 表达"某档额外加条件"，正确做法是给引擎加一个 `when.diffAtLeast` / `when.diffWhen` 之类的作用域字段，而不是把 `diff` 和别的条件平铺在一起。这条留给工程。
