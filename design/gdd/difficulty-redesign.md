## 0. 结论摘要

1. **当前难度的真实问题不是"太简单"，是"没有难度"**：资源全部是展示值，观察系统是装饰，最好的结局是不看任何东西、随便选就能拿到的默认结局（实测见 §1.2）。
2. **难度主轴定为「观察即应答」（Looking is answering）**：看的每一眼是唯一的认知来源，同时也在给门外那个人报坐标。于是"看得越多越懂"和"看得越多越危险"是同一件事——认知压与资源压不靠两套系统叠加，而是同一个动作的两面。
3. **去剧透不等于去掉信息**：把红色左边框换成一套**信号方言**（六个通道，§2），危险仍然可读，但需要玩家学习。信号允许被误读——误读才是恐怖。
4. **所有"一步踏空即结局"改成"欠债"**：6 个此类节点中 4 个改为受伤 / 掉资源 / 失去同伴但继续（§5），并新增 1 个缓冲节点 `k13`（最后一道门），让敲门达到 13 时仍有最后一次自救机会。
5. **真结局必须无法一次通关**：把门槛从"眼睛够多"改成"你读懂了规则且没有把人丢下"，其中一条必需线索**只能通过观察获得**（`saw_sixth`），从物理上堵死一穿（§8.3）。

## 1. 设计支柱与诊断

### 1.1 三条设计支柱（本轮不再新增）

| # | 支柱 | 对难度的要求 | 违反即打回 |
|---|---|---|---|
| P1 | **规则恐怖**：恐怖来自"你必须先弄懂它"，不是来自跳吓 | 每条致命机制都必须有可推演的规律，且规律藏在观察点里 | 任何"随机致死" |
| P2 | **每一眼都要还**：注意力是唯一货币 | 观察必须同时付时间 / 电量 / 敲门；三者都能杀你 | 免费观察、免费读档试错 |
| P3 | **活下来是有代价的**：不做全收集的最优解 | 存在"资源—认知—人性"的三向取舍，最优不是角点而是区间 | 存在一个全优解（既有 §1.2 的默认结局问题） |

### 1.2 实测证据（本轮重跑，结论直接引用，不再重复统计）

我用引擎语义（`check` / `applyEffects` / `route`）写了一个离线模拟器，把三条典型玩家策略跑通全程：

| 策略 | 步数 | 观察 | 电量 | 敲门 | 眼睛 | 复苏 | 结局 |
|---|---|---|---|---|---|---|---|
| **A 随便选**（每次取第一个非 danger 选项，**零观察**） | 64 | 0 | 100 | 15 | 6 | 56 | **`e_true` 真结局** |
| B 全观察 + 首选 | 65 | 26 | **−30** | 42 | 6 | 60 | `e_true` |
| C 全观察 + 避 danger | 64 | 26 | **−25** | 41 | 6 | 56 | `e_true` |

**三条策略全部打到真结局。** 这是本轮所有改动的唯一判据：改完之后，A 必须掉到 `e_alone` / `e_door`。

其余实测缺陷（每条都附证据，§9 汇总）：

- `battery` 可以被观察扣成负数（−30%）：26 处 × 5% = 130% > 100%，且全程没有任何充电来源。
- `knock` 到 41 也只有两行台词（`story3.js:752`），没有上限后果。
- `clock` 只在 4 处被改动，23:20 之后跳到 05:31（`g1` 的 `set`），"距 05:30 不足 30 分"的 HUD 高亮永远不会触发。
- `f10` 第 2 个选项（`minEyes: 6`）**不可达**：进 f10 前眼睛最多 5 只（`d6 +1`、`e7/e7b/e8r +4`），第 6 只只能由 f10 第 1 个选项喂出来。这是个死选项。
- 20 条线索里**只有 2 条必须通过观察获得**（`photo`、`eighth`）；三条被选项门槛消费的线索（`knock_rule` / `knock_rhythm` / `eye_rule`）全都能从选项白拿。观察系统与主线判定之间没有因果。
- 26 个观察点有 1 个完全空转（`p9/o_badge` 给 `{}`）；第四幕操场之后为 0。
- 手动存档 + 每节点自动存档 + 可反复读档 = 试错零成本，任何"代价"都可被撤销。

### 1.3 难度主轴的落地形状

| | **看得少** | **看得多** |
|---|---|---|
| **敲门低** | 无知但活着：能走完，只能拿坏结局 | 开眼但被盯上：有认知，但账单在涨 |
| **敲门高** | 他找不到你：躲过去了，什么也没懂 | 他在门外等你：全知，但只剩一次机会 |

- **认知压**：选项不再标注危险，只有观察能提供"读法"（哪句话会让敲门 +2，哪个动作是正确解）。
- **资源压**：观察同时推进三张账单（时刻 / 电量 / 敲门），而这三张账单的到期日都落在同一晚。
- **交叉点**：`knock` 是唯一"看得越多越危险"的资源，所以"我全都要看"不是最优——**看对**才是。

## 2. 去剧透方案：信号方言（Diegetic Tell System）

### 2.1 为什么不能只是"换个颜色"

`.choice.danger{border-left-color:var(--blood)}`（`css/style.css:435`）的问题不是红色，是**它是一套外挂在地叙事之上的 UI 语言**：玩家读的是按钮的属性，不是场景。把它换成"暗红""虚线""加图标"全都一样，只是把答案换了个字体写在脸上。

正确的做法是**让场景自己说话**，并且让玩家知道自己在学一门方言。原则三条：

1. **双通道**：每个危险选项至少有 2 个通道给出信号，且其中 1 个允许被误读。
2. **低价预演**：每种信号第一次出现时必须配一个"受伤但不死"的后果，让玩家用血学会这个词。
3. **方言会撒谎**：同一信号在不同上下文含义不同（§2.3 的最后两行）。玩家不能建立"看到 X 就安全"的映射表，只能建立"在这类处境里，X 通常意味着……"。

### 2.2 六个通道（与美术圣经对齐）

| # | 通道 | 载体 | 对应 art-bible 条款 | 无障碍 |
|---|---|---|---|---|
| C1 | **光斑语法** | 场景内冷青光斑的**数量**与**位置** | §3.1「冷青 = 唯一冷色 = 光源/出口/活人」、§5.4「光源不超过 2 个」 | 视觉原生 |
| C2 | **血红预算** | 场景内干血红**面积占比**（≤4% 是常态） | §3.1「血红 ≤4%，只用于血/鬼眼/不对劲的点」 | 视觉原生 |
| C3 | **空虚语法** | 场景里**人影数量**与遮挡关系（少一个人 = 他站进去了） | §5.4「每张场景人物数量 = 0，只允许 1 个无五官剪影」 | 视觉原生 |
| C4 | **立绘差分** | 已有差分件的开关与局部替换（不新增美术成本） | §6.5「差分只改局部器官，不改姿态光照」 | 视觉原生 |
| C5 | **环境音 + 字幕轨** | 敲门节奏、锈、水、呼吸；**全部配 `[]` 字幕** | §7.4 文字禁令只限**图内**文字，UI 字幕允许 | 听觉障碍必备 |
| C6 | **排版方言** | 字距、字重、断句、人称（不用颜色） | — | 色盲友好 |

**C1 的具体用法**（本方案里最便宜、最有效的一招）：

> 场景里冷青光斑**从 2 个变成 1 个** = 有一个出口没了或有人站在了光前面。
> 光斑**位置下移**（地面反光）= 他走过来了（老人走路会踩出湿痕）。

**C2 的具体用法**：血红预算从 ≤4% 变成 5–6% 不是"加个红边"，是场景里**多了一处血**——玩家需要自己注意到"这间教室刚才只有一处血"。

### 2.3 信号字典（v1，可被误读）

| 信号 | 通常含义 | 可误读成 | 玩家在哪学会它 |
|---|---|---|---|
| 敲门节奏**停了一拍** | 他在等回应；此刻任何出声 = 应答 | "他走了"（停顿最像安全） | `p16`（周正讲课时的空白）+ 观察点 `o_body` |
| 光斑少一格 | 出口/活人减少 | "更暗了而已" | `c2`（往下走那一格） |
| 血红面积 +1 | 他看过这里 | "刚死过人，所以危险"（其实是"所以他来过，会再来"） | `d4look`（段鹏的尸体） |
| 立绘的"过大的笑"收起来 | 张伟不笑了 = 他真的怕了 = 接下来会死人 | "他镇定了" | `e6`（王珊珊被勒住时） |
| 选项文本变成**短句 + 句号 + 第一人称** | 玩家在做"不解释"的决定，多半是放弃类 | "果断 = 正确" | `f10`（全部五个选项都是这种语法，是正确的） |
| 字幕出现 `[纸]` | 人皮纸在场，说出的"未来"不可信 | "只是道具声" | `c3`（方镜袖子里） |
| 字幕出现 `[呼吸]`（第二个） | 电话那头不是人 | "信号不好" | `f2` |
| 选项里出现**具体数字**（"十三下""七个人"） | 数字是被鬼域写下的，跟着它走 = 进它的账本 | "精确 = 可靠线索"（**这是最长寿的误读**） | `f9` + `o_gate_steps` |

> 最后两行是**故意留的反例**：有些信号的意义是反的。玩家无法用一张表通关，只能用处境推。

### 2.4 具体改法示例（7 个，前 5 个为交付硬要求）

**示例 1 · `p5`「点开那个音频」——把"危险"变成"他被你拽了一下"**

- 现状：`cls:'danger'` 红边 + 选中后 `knock +3`。
- 改法：删 `cls`。选项**上方**插一行非台词文本（`style:'whisper'`，无说话人）：
  > `耳机线在桌上轻轻弹了一下，像有人从另一头拽了拽。`
- 信号：C5（物理声）+ C6（这句是"描写"，不是"判断"）。可误读为**设备故障**。
- 真信号其实在代价里：听完 `knock +4`（原 +3），并且**获得 `audio` 道具**——它是 `d2` 唯一的救命手段。所以这个选项是"高利贷"，不是"陷阱"。

**示例 2 · `f10`「自己一个人冲出校门」——危险写在语法里**

- 现状：五个选项全部红边，等于宣布"这里全是危险"，反而没有信息量。
- 改法：全部删 `cls`。把文本改成第一人称短句：
  - `我跑得比他快。` / `纸上是这么写的。` / `闭上眼睛就好了。`
- 信号：C6——**短句 + 句号 + 不解释**。玩家读三遍会发现"这些句子不是杨间平时说话的方式"（他平时用 `~……~` 内心独白）。判断依据是语气，不是颜色。
- 唯一例外保留在 `f10` 第 1 项上：它的文本是"咬下手臂上的一只眼睛，吞下去。"——**唯一一个动作具体到生理细节的选项**，语法上就与其余四个不同。这就是"正确选项"的标记，但它需要玩家自己发现。

**示例 3 · `e6`「转身跑」——用差分演，不用红边说**

- 现状：`cls:'danger'`，效果是 `left_wang`（王珊珊被拖走）。
- 改法：删 `cls`。选项渲染前 200ms：王珊珊的立绘切到 `wangshanshan_marked`，**只改后颈手印的蔓延范围**（符合 art-bible §6.5 差分规则，零新增资产），并让她的右手从袖口露出来一截（"伸出来的手"= 你将要松手）。
- 信号：C4 + C3（场景里的人数即将 −1）。可误读为"她受伤了，我要去救她"——恰好导向另一个选项。
- 玩家学习点：`m_handprint`（`g4` 的档案）解释了"她没有说谢谢，她只是一直没有松手"。

**示例 4 · `c2`「继续往下走」——用光斑数**

- 现状：红边，通 `c2a` → `c2b` → `c2d`（`e_stairs`）。
- 改法：删 `cls`。选项**出现时**场景从 `stairwell` 切 `stairwell_mirror`（既有资产，`_rot` 不需要新画），镜面里的应急灯光斑**只有 1 处**而现实里有 2 处。
- 信号：C1。可误读为"镜子脏"。
- 后果：`c2a` 起改为 fail-forward（§5），玩家不会一脚踩进 `e_stairs`。

**示例 5 · `d4`「停下来，靠墙站住，屏住呼吸」——纯认知档，UI 什么都不给**

- 现状：红边，通向 `d4stop`（`e_door`）。
- 改法：**不给任何视觉信号**。这是全篇唯一一个"信号为零"的选项，因为正确答案只取决于你**有没有 `knock_rule` 这条线索**：
  - 有 `knock_rule` → 屏息是正解：`knock −2`，`clock +10`，他走过去。
  - 没有 → 你不知道"敲门是在计时"，屏息反而让他确认门后有人 → fail-forward 分支 `d4stop_ff`（被抓伤，`corruption +15`、`battery −10`、`survivors −2`），**继续**。
- 信号：C5 的一处极小细节——选之前环境音里 **敲门声比刚才慢了一拍**。听不出来的玩家就是会挨一下。
- 这一条是"认知压"的样板：不靠 UI，靠你懂不懂规则。

**示例 6 · `f2`「听下去」——第二个呼吸声**

- 现状：红边，`knock +5` 但给出三条线索。
- 改法：删 `cls`。电话接通后，音床叠一层 `breath`，字幕轨打 `[呼吸]`。若玩家在 1.5 秒内没有挂断，再叠第二层。
- 信号：C5（+字幕等价物）。可误读为"电流声"。
- 这里**故意保持"听下去"的收益为正**（拿 `phone_ring/forum_trap` 是 `f6` 串规则的原料），让玩家自己权衡"我要线索还是要命"。

**示例 7 · `c3`「抓住方镜的衣领」——`[纸]`**

- 现状：红边，但实际不是死亡（`grabbed_fangjing` + `corruption +3`）。
- 改法：删 `cls`，加字幕 `[纸]`。方镜的袖子里有纸在响。
- 信号：C5。可误读为"他藏了东西"（对，也确实是），但真危险是"人皮纸会认主"——他会把纸塞给你，`corruption +3`。
- 目的：让"红边"这个历史包袱彻底消失后，玩家还能分辨"这是死亡"和"这是代价"。

## 3. 资源债务表

**所有数值以「标准」难度为基准**，故事/噩梦的倍率见 §6。基准假设：名义通关路径 64 个节点（实测 54–66）。

### 3.0 四张账单的名义收支（标准，64 节点路径）

| 资源 | 期初 | 收入 | 支出 | 期末 | 是否闭环 |
|---|---|---|---|---|---|
| 时刻 `clock` | 22:10（1330） | **无**（单向） | 节点 64×4 = 256；观察 19×6 = 114；剧情固定 +70（`act5`+40、`f5`+30） | 1770 = **05:30** | ✅ 正好用完，超支即提前终局 |
| 电量 `battery` | 100% | 保安亭插排 +20、苗小善卡 +25、卫星电话 +15（合计 +60） | **前段自由**（一幕/二幕观察）；**中段剧本强制**（`d2`→7%、`d4`→5%、`d5`→1%、`d5` 末→0%）；**后段全靠补给**（观察 5%/处） | 前段 100 − 5n → 强制 0 → 后段 0+60−5m | ✅ 下限夹 0；0% 只在"厕所段"这一剧本点发生，之后靠补给点重新点亮 |
| 敲门 `knock` | 0 | 观察 +1/处；回应类选项 +2~+5；03:00 后每 2 节点 +1 | 屏息 −2、关手机 −1、张伟打岔 −3 | 19 + 20 + 12 − 6 = **45 → 已死** | ✅ 13 = 硬阈值（经 `k13` 缓冲） |
| 复苏 `corruption` | 0 | 睁眼 +8、看鬼 +12/+16、鬼婴接触 +18、借力 +10~25、放弃同伴 +6~8 | 掐伤口 −10、念名字 −8、周正忠告 −8 | 8+18+25+5−8 = **48** | ✅ 30 = 力量，60 = 献祭门槛，85 = 强制失控 |

> **注意 knock 那一行**：45 是"全观察 + 每个回应选项都选"的结果，玩家必须在过程中主动把它压回去。这就是本轮新增的"资源管理"手感——**它现在真的会杀你**。

### 3.1 时刻 `clock`

| 项 | 内容 |
|---|---|
| **获得** | 无。时间只往前。这是全篇唯一不可再生的资源，也是唯一的"总预算" |
| **消耗** | 节点基础 4 分（进节点即扣，含纯旁白节点）；观察 6 分/处；剧情固定：`act5` 选去校门 +40 / 选坐下想 +35、`f5` 选重看帖 +30 / 选跑 +25；受伤附加：`left ankle_hurt` / `hand_hurt` / `wrist_hurt` 时每观察再 +2。**除以上四项外不设其他时间消耗**——账目必须可核算，否则 440 分的预算会被隐形开销吃掉 |
| **阈值** | **03:00**（1460 分）→ 敲门开始自动增长（他不再需要你回应）；**04:05**（`act5` 幕首）→ 校门外的车灯全部熄灭，所有 `light:2` 观察点照距减半；**05:10** → 广播报时一次（旁白："远处有人家的收音机响了，报时五点十分。"）；**05:30** → 强制进入 `f10`，HUD 转红 + 一次报时旁白。**不裁剪任何选项**（见下方修正） |

**闭环链（时刻）**：想看清楚 → 观察 +6 分 → 03:00 后每 2 节点额外推敲门 → 时间与敲门双涨 → 你被迫在"再看一处"和"还活着走完"之间选 → **少看的那一处就是少一条活路**。

### 3.2 电量 `battery`

> **修正前提（重要）**：现有旁白已经写死了三个电量数字——`d2`「电量：*7%*」（`story2.js:344`）、`d4`「电量：5%」（`:423`）、`d5`「电量：*1%*」→「正在自动关机」（`:493`）——但**代码从未改动 `stats.battery`**，所以 HUD 会一直显示 100%，旁白与数值完全脱钩（缺陷 D14）。本节的方案不改一个字台词，只补 `set`。
> 结果是一个**三段式电量曲线**，恰好是本作最需要的难度形状：前段宽裕（允许探索）、中段归零（强制紧张）、后段靠补给（第四幕的观察变成奢侈品）。

| 项 | 内容 |
|---|---|
| **获得** | ① `f1` 保安亭插排（观察点 `o_gate_socket`，+20%，一次性）；② 苗小善减压卡 `ms_battery`（+25%）；③ `e1` 周正的卫星电话（+15%，随 `phone` 道具，一次性）。后段可用总量 **60%** |
| **消耗** | **前段（一幕 / 二幕）**：观察 −5%/处；`d1`「打开手机灯」−20%。**中段（剧本强制）**：`d2` `set:7`、`d4` `set:5`、`d5` `set:1` → 节点末 `set:0`（对齐旁白"自动关机"）。**后段（第四幕 / 终幕）**：观察 −5%/处 |
| **阈值** | `≥60%` 照距 3.0 m → 所有观察点可用电量支付；`30–59%` 照距 1.5 m → `light:2` 观察点"一团黑，看不清"（**只能用眼睛付，且单价翻倍**）；`1–29%` 照距 0.8 m → `light:2` 只能靠眼睛；`0%` 手机作废（此后所有照明走眼睛通道） |
| **后果** | 电量归零**不会锁死观察**（眼睛可以代付），但会把代价全部转成 `corruption`——于是"没电"的真正惩罚是"你必须更像鬼才能看见"。同时 0% 会关闭：`d1` 开灯、`d2` 录音（**唯一的救命手段**）、`f2/f3` "看清屏幕"分支。第四幕如果没拿到 `o_gate_socket(+20)` 与 `ms_battery(+25)`，后段 11 处观察将全部以 `corruption +3~+5` 计价 |
| **可读反馈** | HUD 电量（既有）；屏幕四角暗角随电量线性加深（`opacity: (100−battery)/140`）；`≤30%` 时 HUD 数字旁加一个静止的心跳图标；每次观察后 toast 已写"电量 −5%"；**中段强制消耗时不给 toast**（旁白已经在说 7%、5%、1%，再弹 toast 就重复了） |

**照明替代支付（本方案的关键机制，解决"后段没电就只能瞎着"的死结）**

`d6` 之后你身上长了一只眼睛。它不需要电。所以从 `d6` 起，任何观察点都接受**两种货币**：

| 支付方式 | 条件 | 代价 |
|---|---|---|
| 用电量（手机） | `battery ≥` 该点的照距阈值 | −5% |
| **用眼睛（鬼眼）** | 无条件（只要 `eyes ≥ 1`） | **`corruption +3`**（`light:2` 的点 +5） |

- 优先级：引擎默认先扣电量；电量不足时**不锁定，而是切换成"用眼睛看"**（按钮上出现一行小字：`（用这只眼睛看）`）。
- 于是后段的取舍变成：**你愿意为这一眼，更像鬼一点吗？**
- 这一条同时解决了三件事：① 后段电量归零不会让 11 个新观察点变成摆设；② 复苏有了持续的正反馈来源（不再只靠 5 个节点的一次性事件）；③ "全收集"与"真结局"被资源地物理分开——**看全的人一定超过 `corruption 60`，咬不了那只眼睛**。

**闭环链（电量）· 准确版**

```
【前段】一幕/二幕，100% 很宽裕
   观察 n 处 (−5n)  或  开灯 (−20%)
        ↓ 想全看？可以。代价是你把电花在了"看"
【中段】厕所：d2 强制 7% → d4 5% → d5 1% → 0%（旁白已写死，补 set 对齐）
        ↓ 此刻你在黑暗里，什么都看不见——这正是剧本要的
【转折】d6：眼睛钻进来。从此照明可以用"复苏"支付
【后段】第四幕：电量靠三个补给源（20+25+15=60%），不够就烧人性
        ↓ 看得越多 → corruption 越接近 60/85
   ≥60：还能活着走完，但咬不了那只眼睛（真结局关闭）
   ≥85：幕末被强制带进 end_absorb
```

**反向也成立（这是最关键的一处账）**：`o_gate_socket` 只 +20%，而 `d1` 开一次灯要 −20% —— **开一次灯等于用掉整个充电宝的后段份额**。开灯的收益是 `d4look` 里看清段鹏的脸（`ghost_slave` 线索 + 立绘冲击），这个取舍是真的，而且它发生在**第一幕**——玩家会为"第一幕的好奇"付第四幕的账。这是本作唯一一处跨幕的延迟结算，建议在 §6 之外单独测。

## 4. 观察机制延伸

### 4.1 代价模型（新增属性）

每个观察点在既有 `{id,label,x,y,text,effects,free}` 之外增加两个字段：

| 字段 | 取值 | 含义 |
|---|---|---|
| `light` | `0` / `1` / `2` | `0` = **不需要照明**（鬼眼、发光物、晨光——见下）；`1` = 近景，摸得到；`2` = 需要照明（只能用"电量"或"复苏"之一支付） |
| `risk` | `0` / `1` / `2` / `3` | 额外敲门值（叠在基础 +1 之上）。`3` = 你在盯着他看 |

`light: 0` 的依据是文本本身：`d6` 末两句是「黑暗退了。」「周围的一切，都能看见了。」（`story2.js:529-530`）——**第四幕·眼睛（`d7`）的四个观察点必须免费**，否则会出现"旁白说你什么都看得见，UI 说你什么都看不见"的自相矛盾。同理 `终幕` 是晨光，`o_end_lamp` 为 `light:0`。

代价公式（标准）：

```
观察成本 = 时刻 +6 分
         + 按钮基础敲门 +1 + risk
         + 照明费（三选一）：
             light===0                                    → 0
             battery ≥ 照距阈值                             → 电量 −5%
             battery < 照距阈值 且 eyes ≥ 1                 → 复苏 +3（light:2 为 +5）
             battery < 照距阈值 且 eyes ===0                → 【不可点】"太黑了，手机照不到"
         + (flag ankle_hurt ? 时刻再 +2 : 0)
```

> `eyes === 0` 只可能发生在 `d6` 之前（`d6` 必得 1 只眼），所以"不可点"这个分支实际只影响序幕到厕所段——而那一段电量是满的。**净效果：全篇没有一个观察点会永久锁死**，只会变贵。这是"每条必需线索都可获得"的结构性保证。
>
> **复苏 ≥30 之后**，`light:1` 的电量消耗变为 0（眼睛替你照明，不再收费）——这是"力量"最直观的回报，也是"人味越少，看得越清楚"的机制化表达。

## 5. Fail-forward：把"死亡"换成"欠债"

### 5.1 原理

"选错即结局"的问题不是残酷，是**它惩罚的是好奇心**——而好奇心是这款游戏唯一的驱动力。所以惩罚要改成**债务**：你还活着，但你欠了一笔，必须在后面还。三档债务：

| 债务类型 | 表现形式 | 还款点 |
|---|---|---|
| **伤**（wound） | `flag ankle_hurt` / `hand_hurt` → 后续观察 +2 时刻（走不快） | 无（本局永久） |
| **失**（loss） | `survivors −1~2`，且关掉对应同伴卡 | 无（永久） |
| **账**（debt） | `knock +2~5` / `corruption +8~15` / `battery −10` | 可还（屏息 / 掐伤口 / 充电） |

### 5.2 当前 6 个"一步踏空即结局"节点：4 改 2 留

| 节点 | 现状 | 处理 | 新走向 |
|---|---|---|---|
| `c2a` → `c2b`（再往下走） | 通向 `c2d` 即死 | **改 FF** | 踩空、手腕被抓住：`survivors −1`、`corruption +8`、`clock +15`、得 `ghost_slave` → 回 `c2c` |
| `c2b` → `c2d`（继续往下） | 通向 `c2d` 即死 | **改 FF** | 水没过脚踝、电流啪一声：`battery −10`、`corruption +10`、`flag ankle_hurt` → 回 `c2c` |
| `d4` → `d4stop`（屏息） | 即死 `e_door` | **改 FF** | 无 `knock_rule` 且复苏 <60：后脑被按住，`corruption +15`、`battery −10`、`survivors −2`，然后他走了（`d4stop_ff`）→ 回 `d5`；复苏 ≥60 才走旧 `d4stop` |
| `d5`（转身面对它） | 即死 `e_door` | **改明示** | 文本改「我不跑了。我要看清他是什么。」——玩家明确在放弃，保留 `e_door` |
| `c2d`（站着听完） | 即死 `e_stairs` | **改明示** | 文本改「我不数了。数到第几层都一样。」——保留 `e_stairs`，但只能由 `c2c` 主动进入（不再从 `c2a/c2b` 滑进来） |
| `f12c`（闭上眼睛） | 即死 `e_door` | **改明示** | 文本改「闭上眼睛，就不用看了。」——保留 |

**结论**：4/6 改为 fail-forward（67%，超过一半要求）；剩下 2 个（`d5`、`f12c`）加上 `c2d` 改为"玩家明确放弃的承诺"，语法上不再伪装成普通选项。

### 5.3 新增缓冲节点 `k13`（最后一道门）

`knock ≥ 13` 时不再直接死亡，而是强制进入 `k13`：

```
k13（敲门声停在第十三下）
├─ A「屏住呼吸，一动不动。」  需 knock_rule  → knock = 10，clock +20，survivors −1 → 回主线当前节点
├─ B「把手机音量开到最大。」  → knock +5（继续超限）→ e_door
└─ C「推开门。」              → e_door（明示）
```

- 标准/噩梦：A 可用（噩梦下 `clock +30`、`survivors −2`）。
- 故事：不触发 `k13`（`knock` 达 13 只加压迫音效与旁白）。
- 设计意图：给"看得太多"的玩家一次真实的险，而不是一次无意义的处决。

**为什么第四条门槛用 `no_answer` 而不是 `paper_rule`**（T7 实测修正）：

- `paper_rule` 有两个来源：`f8:1`（方镜电话）**和 `d7/t_skins`（观察白骨树上的人皮）**。全观察流恰好会看 `t_skins`，所以它照样拿得到——这条门槛**拦不住它**，只会误杀"拒绝给方镜打电话"的玩家（QA 的 P3 走线正是 `f7:'不打'`）。
- `no_answer` 是纯选项线索，且必须发生在 `f2`。于是门槛的含义变成"**你有没有真的站在校门口，听懂那通电话接通的不是线路**"——这正是第四幕的功课。

## 11. 风险、取舍与待用户拍板

### 11.1 我认为最容易被工程实现打折扣的 2 处

1. **「信号方言」需要三条管线同时落地（C1 光斑 / C4 差分 / C6 排版）。** 工程最容易的做法是"把 `border-left-color` 换个色值"——这会让 §2 的全部设计归零，而且**比现状更糟**（现状至少诚实：红边明确说"这里危险"；换个颜色则既不诚实也不清晰）。如果只做一条通道，正确的最小实现是 **C6 排版**（纯 CSS，零资产）：短句/句号/第一人称的语法标记 + 危险选项 hover 时不放大。它便宜、色盲友好、且不需要美术配合。
2. **「观察即应答」要求把 `knock` 从展示值改成判定值**（13 硬阈值 + 03:00 自动增长 + 屏息 sink + `k13` 缓冲），并且要求实现"眼睛照明"（§3.2）。工程上最容易被降级成"knock 还是只是数字，顶多加个 warning 色""电量不够就锁死观察点"。一旦这两条被降级：§3.3 的整条闭环消失（认知压只剩"有没有线索"）；§3.2 的后段 11 个新观察点有一半变成摆设（因为中段剧本强制 0%）；难度退回单轴。**最小可接受实现**：`knock` 阈值 + `k13` 必须做；"眼睛照明"若砍，必须同时把 `d5` 的强制 0% 改成 `set:20`，否则后段机制全废。

### 12.2 时间锚点与分段预算（取代 §3.0 的全局求和）

原文把时刻写死在三个地方，所以时间只能**分段**核算：

| 锚点 | 出处 | 时刻 | 段内节点数（名义） | 段内预算 | 观察额度 |
|---|---|---|---|---|---|
| 开局 | `STORY.meta.startClock` | **22:10** | — | — | — |
| 到达操场 | `act5.actCard`「四点零五分」+ 苗小善台词「我的表怎么是凌晨四点」 | **04:05**（`atLeast: 245`） | 45–48 | 标准 355 − 45×6 = **85** | 标准 **14 处** / 噩梦 5 / 故事 全部 |
| 老人现身 | `f9` 旁白「五点二十九分」 | **05:25**（`atLeast: 325`），`f10` 幕首再 `atLeast: 329` | 16 | 标准 84 − 16×3 = **36** | 标准 **6 处** / 噩梦 2 / 故事 全部 |
| 终幕 | `g1.enter.set.clock = 331` | **05:31** | 7 | 不计时 | 免费（时间 0） |

- 三处 `set` 是**硬锚点**：段内花超了就到锚点为止（等于"你在黑暗里发了一会儿呆"，这在鬼域里是合理的），花少了也会被 `set` 推过去，所以**永远不会有"到不了操场"或"提前天亮"的情况**。
- 由此得到终值：**标准档 14 + 6 + 3 = 23 处可看**（62%），**噩梦 5 + 2 + 3 = 10 处**（27%），**故事 37 处全看**。
- **锚点必须用 `max(当前, 锚点)` 而不是赋值**（`clock = Math.max(clock, anchor)`）。否则：前三幕 26 处全看的玩家会走到 04:16，`act5` 一赋值就把他**送回 04:05**——时间倒流，而且他的贪婪白费了。用 `max` 之后，"前三幕看得太贪"会真的吃掉第四幕的额度（04:16 → 只剩 73 分钟 → 四幕只能看 1 处），这才是跨幕延迟结算。
- 落地动作：`act5.enter` 加 `set:{clock:245}`；`f9` 加 `set:{clock:329}`（`g1` 已有 331，不动）。
- `nodeCost` 取值：`n.pace === 'run' ? run : (n.pace === 'still' ? 0 : walk)`；四幕节点建议统一加 `pace:'run'`，终幕加 `pace:'still'`。
- **`f9` 取 05:25（325）而不是 05:29**，留 4 分钟给 `o_gate_steps` 那一处观察；`f10` 幕首再 `atLeast: 329`。否则玩家在 `f9` 看一处就把时钟推过 05:30，`f10` 的门槛判定会因为他"看得太仔细"而失效。

**回滚必须做的两个夹取（否则会死循环）**

```js
// 回滚后立刻夹，顺序不能反：先加惩罚，再夹上限
state.stats.knock      = Math.min(state.stats.knock + penalty.knock, d.knock.danger - 1); // 噩梦 = 9
state.stats.corruption = Math.min(state.stats.corruption, d.corruption.brk - 15);          // 噩梦 = 60
```

- **为什么要夹 knock**：噩梦 `k13 = 11`，从 `e_door` 回滚后再 `+3`，如果原本 knock 已是 11，回滚后仍是 11 → 下一个节点立刻再进 `k13` → 再死 → 回滚次数被瞬间吃光。夹到 `danger − 1 = 9` 才能保证"回滚之后至少还能活一个节点"。
- **为什么要夹 corruption**：`e_absorb` 的触发条件是 `≥85`（噩梦 75）。不夹的话回滚后仍是 85+，幕末检查会立刻再判一次失控，形成"回滚 → 失控 → 回滚"的死循环。夹到 `brk − 15`（噩梦 60）留出一个安全窗。

**确认 team-lead 提的两处偏差**：惩罚是 **knock +3 / survivors −1**（不是我原文的 +3/−1？是；也不是工程说的 +2），回滚上限噩梦 3 / 标准 5。

### 12.14 全观察流为什么仍拿 `e_true`（复核结论）

补 `pace` 之后重跑，标准档 P2（全观察）**仍然拿到 `e_true`**。原因是两条，都不是时间：

1. **`f9` 被跳过**。P2 在 `act5@04:57` 被拽去 `f10`，而 `f9` 是四个复苏幕末判定点之一（`CORRUPTION_BREAK_NODES = ['act3','d8','act5','f9']`）。跳过 `f9` 就跳过了一次"你该变成鬼了"的检查。
2. **即使跑到 `f9` 也判不出来**。P2 终态复苏 100，但那是**后段**堆出来的：减去 `f10` 咬眼 +25、`g1` +5、终幕三处观察 +12，`f9` 那一刻大约只有 **55–60**，离 `brk 85` 差着 25 点以上。**"看全"不等于"复苏高"**：`corruption` 是"碰鬼"的账（`d6`、`e7`、`d7b` 三个事件就占了 42），不是"看"的账——24 处观察里只有 `t_nail` 一处会涨复苏。

所以 §3.4 里"全收集者必然超过 60、咬不了那只眼睛"这个推断是**错的**：P2 到 `f10` 时复苏约 58，仍在 `maxCorruption:60` 之下，咬眼完全合法。

**已落地（T7）**：真结局门槛加了第四条线索，但**不是 `paper_rule`，而是 `no_answer`**，原因见 §8.3 的实测修正（`paper_rule` 有两个来源，全观察流会从 `d7/t_skins` 拿到，拦不住）。

```js
// js/story4.js · g7 第 1 项
when: { notFlag: 'left_wang', minSurvivors: 5,
        allClues: ['eye_rule', 'saw_sixth', 'ghost_domain', 'no_answer'] }
```

**T7 实测（`node tests/qa_time.js`，标准档）**：

|---|---|---|---|

| P2 全观察 | `e_true` | 自然 | **这一跑没有被拽**：`act5 > f1 > f2 > … > f9 > f10` 全走过，`f2`/`f8` 都在序列里，`no_answer` 是自己挣的 |
| P3 最少观察 | `e_true` | 03:59 | ✓ |

**所以"全观察仍拿真结局"这句话要拆成两半**：

1. **被拽走的那种 P2**：确实拿不到了——它到不了 `f2`，`no_answer` 无从获得。门槛在这个方向上是有效的。
2. **没被拽、一路看下来的 P2**：它把第四幕走完了、也把 `no_answer` 拿到了，凭什么是"漏洞"？它只是花了 27 处观察、knock 52、复苏 100 的代价——**而这三样都没能拦住它**。

第 2 条才是真正没解决的问题，且不在"结局门槛"这一层：

- **`k13` 一局只触发一次**（`__k13` 置位后不再进入），所以 knock 52 只挨了一次罚（−3 敲 / −1 同伴）。
- **复苏只在 4 个幕末节点结算**（`act3` / `d8` / `act5` / `f9`），而 P2 的复苏是在 `f10` 之后才堆到 100 的（咬眼 +25、终幕观察 +12），四道闸门全部错过。

这两条都属于引擎/机制层，不是数据能补的。**我的建议（留给你拍）**：把 `f10` 与 `g1` 也加进 `CORRUPTION_BREAK_NODES`——前者是"你咬了那只眼睛"，后者是"你走到了天亮"，两个都是天然的审判点。加进去之后，P2 这类"后段堆复苏"的玩法会在 `g1` 被判成 `end_absorb`，而 P3（`g1` 时复苏 63）安全通过。

**为什么不用 `maxCorruption` 当门槛**：实测 P3（目标路线）在引擎里的终态复苏也是 **100**（眼睛照明在电量不足时按 3/5 点收费，标准档后期一路烧人性）。P2 与 P3 在复苏上分不开，加 `maxCorruption` 只会把目标路线一起误杀。

### 12.15 已签字的取舍（R2 / R3 / R4）

> **这一节是"不要再动"的清单。** 以下三条在验收时被判定为 CONCERNS，由主理人签字确认为**有意为之**。下一个人看到它们时，第一反应多半是"这是个 bug，改掉"——**请不要改**。每条都写了"为什么不是 bug"和"具体不许动哪个数字"。

#### R2 · 故事档全观察仍能拿 `e_true`（`corruption.brk = 95`）

| 项 | 内容 |
|---|---|
| **现象** | 故事档（`brk 95`、观察耗电 3%、敲门 0.5/处）下，把 37 处观察点全看完也几乎不可能被判失控，最后照样能拿「五点三十一分」。 |
| **判定** | **接受。不压 `brk`，不调故事档的观察代价。** |
| **为什么不是 bug** | 三档的差异**本来就该是"要不要取舍"，不是"惩罚有多重"**。故事档的定位是"把这一夜看完"——它卖的是叙事完整度，不是资源管理。一个想看懂全部伏笔的玩家，在故事档不该被资源系统拦在门外；他要是想要取舍，标准档就在旁边。 |
| **具体不许动** | `DIFFICULTY.story.corruption.brk` 保持 **95**；故事档的 `BATTERY_VISIBLE` 保持 `dimWhenLow:false`（不吞观察点）；不要给故事档加 `maxCorruption` 之类的结局门槛。 |

> 注意：故事档"不惩罚贪看"只对**复苏**成立。时间（`clock`）与敲门在故事档仍然计费——只是它们不会把玩家判死，只影响旁白与结局倾向。这条边界别搞混。

#### R3 · 真结局窗口偏窄（标准档复苏余 7，噩梦敲门余 1–3）

| 项 | 内容 |
|---|---|
| **现象** | 走到 `e_true` 的容错极小：标准档在 `f10` 咬眼那一刻，复苏距 `maxCorruption:60` 只剩 **7** 点；噩梦档敲门距 `k13 = 11` 只剩 **1–3** 点（参考路线跑出 3，见 §12.13）。 |
| **判定** | **接受。不调 `k13`，不调 `maxCorruption`，不调 `brk`。** |
| **为什么不是 bug** | 真结局本来就该是**窄门**——它是全篇唯一"活着并且带着人一起"的结局，如果它和 `e_alone` 一样容易，那七个结局就没有叙事重量了。噩梦档的定位是**专家模式**，"接近零失误"是它该有的样子；验收里"噩梦很难"不是缺陷，是产品定位。 |
| **具体不许动** | 噩梦 `knock.k13` 保持 **11**；`f10:1` 的 `maxCorruption` 保持 **60**；三档 `corruption.brk` 保持 **25/60/95 · 30/60/85 · 30/55/75**。 |

> 唯一**允许**的调整方向（如果将来真要放宽）：降"回应类选项"的敲门单价，而不是抬阈值。理由：阈值决定"多难算死"，单价决定"多难避免"——前者一改，所有存档的手感同时变；后者只是让玩家少挨一下。

#### R4 · 复苏判定发生在 `enter` 之前，`g1` 自身的 `+5` 不会致死

| 项 | 内容 |
|---|---|
| **现象** | `runNode()` 的顺序是 `chargeNodeClock → forcedTarget（含复苏失控判定）→ applyEnter`。所以走到终幕 `g1` 时，系统先按**到达那一刻**的复苏判一次，之后才结算 `g1.enter` 的 `+5`。结果是：一个带着 **74** 点复苏走到噩梦黎明的人不会被判死（噩梦 `brk = 75`，74 差 1 点过关），`+5` 之后变成 79——越过了线，但那一刻已经不再判了。他"贴着线活着"走到了天亮。 |
| **判定** | **接受。保持 `enter` 前判定，不要为了"更严"把判定挪到 `enter` 之后。** |
| **为什么不是 bug** | `g1` 是**"你走到了天亮"的落点，不是第二次审判**。它的 `+5` 是叙事加冕（你身上带着那只眼睛活到了早上），不是又一次伤害结算。如果判定放在 `enter` 之后，就会出现"刚走到黎明、被自己脚下的 +5 判死"这种荒谬结果——玩家会觉得是游戏算错了，而不是自己输了。 |
| **具体不许动** | `runNode` 里 `forcedTarget()` 与 `applyEnter()` 的**先后顺序**；`g1.enter` 的 `{ set:{survivors:7,clock:331}, stats:{corruption:5} }` 保持原样；不要给 `g1` 单独加"到达即判"的钩子。 |

> 这条有个连带效果值得知道：`g1` 之后**再也没有幕末判定点**，所以"在 `f10` 之后堆复苏"在当前结构下不会被追罚。这是 R4 的代价，不是 R4 的漏洞——如果未来要把审判延伸到终幕，正确做法是**新增判定点**（例如 `g7`），而不是把 `g1` 的判定挪后。

### 13.3 `k13` 的出口契约（**必须由引擎补一行**）

`k13_pass` 的 `route` 需要一个"被打断的节点"才能回到主线：

```js
route: s => {
  const back = s.flags.__k13_back;                 // ← 引擎应写这个
  if (back && STORY.nodes[back]) return back;
  const act = s.actStart;                          // 兜底 1：回到本幕幕首
  if (act && STORY.nodes[act]) return act;
  return 'd4';                                     // 兜底 2
}
```

**引擎需要在 `forcedTarget()` 返回 `{node:'k13'}` 之前写 `state.flags.__k13_back = targetId;`**（`targetId` 就是本来要进的那个节点，函数签名里已有）。

没有这一行时：`k13` 之后会退回本幕幕首，**整幕重播、时间被二次消耗**——实测会让"全观察"路线在第四幕前就把时间烧光，`e_written` / `e_true` 的引导通关全部失败（`tests/run.js` 里 12 项由此而来，补上后可回到 2 项）。

### 13.4 `REQUIRED_CLUES` 的隐藏耦合（给工程与后续设计者的提醒）

`hotspotTier()` 把"被任何 `when` 消费的线索"判定为 `key`。所以**只要给某个选项加一条 `allClues`，所有授予该线索的观察点都会瞬间升级成 `key`**，低电量时的吞并顺序也随之改变。

本次 B12 加入 `ghost_domain` 之后，`d7/t_tree` 从 `ref` 变成 `key`，`tests` 里"关键线索优先留下"那条断言（期望 `t_nail` + `t_eye` 留下）因此失效。这是预期副作用，不是数据错误。

## 14. 理智系统（另见）

第 7 个资源 `sanity`（理智）的完整设计在 **`design/gdd/sanity-system.md`**，本文不复制。只在这里留四条接口约定，免得两份文档打架：

1. **分工**：`corruption` 收"动手"的钱（碰鬼、睁眼、咬眼），`sanity` 收"看懂"的钱（看见、听见、想通、丢下人）。同一动作不在两条账上同时收——唯一例外是 `f10` 咬眼（`corruption +25` / `sanity −20`），因为吃自己的眼睛既是身体事件也是精神事件。
2. **不致死**：`sanity` 到 0 触发 `sanityBreak`（**回到触发断片的那个节点** / `clock +30` / 恢复 40），**不影响**本文 §12.5 的死亡判定与回滚表。两条线互不接管；注意它与"死亡回滚到场景开头"是两套粒度，别混。
3. **不动观察的代价**：观察仍然付 `clock / battery / knock`（§12.1 不变）。`sanity` 只是在**特定观察点**上追加的第四种成本，且 **key 级观察点恒为 0**（结构保证，与 §12.3 的 `noDim` 同一条思路）。
4. **故事档一致**：故事档**不因理智锁任何选项**，只改文本与表现——与 §12.15 已签字的 R2（故事档不惩罚贪看）是同一条原则。
