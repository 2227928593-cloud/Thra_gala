## 一、结论摘要

本次测试共设计并执行 **98 个用例**（核心功能 74 项 + 剧情可达性 24 项），另加 **120 次随机通关压力测试**。结果：**88 项通过，10 项失败**——而这 10 项失败**全部**对应下文记录的 10 个缺陷，没有出现任何"说不清原因"的失败。

**关键结论：README 承诺的核心内容有相当一部分在成品中无法触达。**

| 严重度 | 数量 | 摘要 |
|---|---|---|
| **P0 阻断** | 2 | ①第 5 个结局「第八个人」**永远无法达成**；②**11 条档案**（2 线索 + 9 档案）**永远无法解锁** |
| **P1 高** | 3 | ③HUD「档案」按钮**永远显示空档案**；④观察模式**每看一处就强制退出**，看完最后一处**抛异常**；⑤整段 `e7b` 剧情是**死代码** |
| **P2 中** | 2 | ⑥线索档案**跨局不永久解锁**（与 README 承诺矛盾）；⑦HUD 时刻 `deadline` 判定恒真且**没有对应样式** |
| **P3 低** | 6 | ⑧O 键提示不显示；⑨`?auto=1` 冒烟模式死锁；⑩两张立绘从未出场 + 1 处立绘路径不存在；⑪重复/未引用的美术资源；⑫无用字段与未完成的电量机制；⑬README 节点数不符 |

值得肯定的是：**存档/读档、设定持久化、结局回廊、键盘操作、音频降级、剧情数值健全性均表现良好**，120 次随机通关没有出现一次卡死、异常或数值越界。6 个可达结局都能通过真实引擎稳定通关。

## 二、测试范围与方法

### 2.1 为什么用"真实引擎 + 最小 DOM"而不是浏览器自动化

本项目是纯前端 `file://` 可运行的页面，最理想的测试方式是真浏览器驱动。但在当前沙箱环境下：

- Node.js 通过 `child_process.spawn` 启动 Edge 会被沙箱直接终止（进程退出码 `0x80000003`）；
- 由 PowerShell `Start-Process` 启动的 headless 实例，CDP 端口时好时坏，无法作为稳定测试底座。

因此改用**保真度更高的替代方案**：用 Node 实现一个最小 DOM（`tests/dom.js`，含选择器引擎、`classList`/`dataset`/`hidden` 属性反映、`innerHTML` 解析、事件冒泡、`closest`），在 `vm` 上下文中加载**真实的 `index.html` 与全部 `js/*.js`**（`tests/harness.js`），然后驱动真实 `engine.js` 跑完整剧情。

- 测的是**生产代码本身**（`engine.js` / `audio.js` / 全部剧情数据），不是重写的模型；
- 引擎的所有定时器被替换为**虚拟时钟**，可用毫秒级速度推进整局游戏，并支持"只推进 N 毫秒"以观察 toast 这类瞬时 UI；
- 唯一无法覆盖的是 CSS 渲染、字体、动画与真实音频输出（见第六节）。

### 2.2 测试资产

| 文件 | 作用 |

## 三、缺陷清单

### P0-1　第 5 个结局「第八个人」永远无法达成

**现象**：README 与结局回廊都宣称有 7 个结局，但「第八个人」（`e_eighth`）在任何玩法下都无法触发。测试用 25 次针对性引导（专门优先选择「转身，跑。」与「回头去找那个第八个人」）全部失败；120 次随机通关也只覆盖到 6 个结局。

**根因（完整因果链）**：

1. 旗帜 `left_wang` 在全项目中**只有一处被设置**：`js/story3.js:227`，即鬼婴场景里选择「转身，跑。」（放弃王珊珊）。
2. 通往终幕必须经过 `f10`（`js/story3.js:752-757`）的五个选项，而其中能走到终幕的只有前两个：
   - 「咬下手臂上的一只眼睛，吞下去。」→ 需要 `allClues:['eye_rule']` 且 `minEyes: 5`
   - 「把所有人聚在一起，用鬼域罩住他们。」→ 需要 `minEyes: 6`
   - 其余三个（冲出校门 / 打开羊皮纸 / 闭上眼睛）分别直达 `e_alone` / `e_written` / `e_door`，**都到不了 `g7`**。
3. 鬼眼（`eyes`）全项目只有三个来源：
   - `js/story2.js:530` d7「站起来，看清这里。」→ **+1**
   - `js/story3.js:255` e7「咬紧牙，撑过去。」→ **+4**
   - `js/story3.js:279` e7b「撑住。」→ **+4**（该节点本身不可达，见 P1-3）
4. 而 e7 只能通过 `e6` 选「冲过去，一拳砸在鬼婴脸上」进入——**与设置 `left_wang` 的「转身，跑。」互斥**。

因此：**一旦放弃王珊珊，鬼眼最多只有 1 只**，`f10` 的两个通道全部因 `minEyes 5/6` 锁死，玩家必然走向 `e_alone`/`e_written`/`e_door` 之一，永远到不了 `g7`。`g7` 上以 `flag:left_wang` 为条件的选项 4「回头去找那个第八个人」（`js/story4.js:281`）连同整个 `end_eighth` 节点都是**死选项/死内容**。

**证据**：`tests/prove_eighth.js` 对 `e7r` 之后的子图做了穷举（1099 个状态，剧情图无环故为完备搜索）：

```
=== 场景 A：放弃王珊珊（left_wang = true），从 e7r 继续 ===
  到达节点数: 19 | 状态数: 1099
  可达结局: e_alone, e_door, e_written
  是否到达终幕 g7: 否
  是否到达 end_eighth: 否
  是否到达 f11（通往终幕的节点）: 否
```

**连带影响**：`g1b`（未救王珊珊的终幕分支）、`end_eighth` 节点、`e_eighth` 结局、`eighth` 档案条目、`left_wang` 相关的全部条件判断，构成一条彻底废置的分支。

**建议（任选其一）**：
- 让 `e7b` 可达（见 P1-3），使「有张伟帮忙」的救人路线能同时满足"救下王珊珊"与通过条件；
- 或为 `left_wang` 分支补一条独立的、不经 `f10` 鬼眼门槛的终幕通路；
- 或降低 `f10` 的门槛（例如让「闭眼等死」也能引出 `g7`）。

### P1-3　HUD 右上角「档案」按钮永远显示空档案

**现象**：游戏中点击 HUD 的「档案」按钮，档案面板**永远是空的**（"还没有记下任何东西。"），即使刚刚拾取过线索。用 `C` 键、暂停菜单、标题页进入则一切正常。

**根因**：`js/engine.js:117`

```js
$('#btn-codex').addEventListener('click', openCodex);
```

直接把 `openCodex` 作为监听器，浏览器会把 `MouseEvent` 当作第一个实参传入，于是：

```js
function openCodex(tab) { renderCodex(tab || ...); }   // tab === MouseEvent
function renderCodex(tab) { const data = CODEX[tab] || []; }  // CODEX[MouseEvent] → undefined → []
```

**证据**（同一局，同一状态，两种入口对比）：

```
clues: ["photo"]
[HUD 档案按钮] body: "还没有记下任何东西。"
[openCodex() 无参] body: "老人照片论坛里那张照片：黑色长衫，褐色皮肤，尸斑…"
```

**影响**：这是玩家在游戏中最常用的档案入口，功能完全失效。

**建议**：改为 `$('#btn-codex').addEventListener('click', () => openCodex());`

### P1-4　观察模式：每看一处就被强制退出，看完最后一处抛异常

**现象**（两个互相纠缠的症状）：

1. 看完 **1 个**热点并关闭卡片后，引擎**立刻退出观察模式并清空整个观察层**，剩余未看的热点全部消失，必须重新点「观察四周」才能继续；「还剩 N 处」提示也不再更新。
2. 看完 **最后 1 个**热点并关闭卡片时，引擎**抛出 `TypeError: Cannot read properties of null (reading 'length')`**（`js/engine.js:670`），异常发生在 click 回调内，观察层不会被清理，玩家停留在**没有任何热点的观察界面**，只能手动点「退开」离开。

**根因**：`js/engine.js:670`（`refreshObserveEntry`）

```js
const remain = $('#observe-layer .hotspot:not(.found)').length;
```

- `$` 是 `querySelector`，返回**单个元素或 `null`**，不是数组；
- 单个元素的 `.length` 是 `undefined`，`undefined > 0` 恒为 `false` → **每次都直接走 `exitObserve()` 并清空观察层**；
- 当已无未看热点时 `$()` 返回 `null`，读 `null.length` → **抛 TypeError**。

**证据**：

```
[看 1 处并关闭]  after close -> observeOpen: false | hotspots: 0
[看最后 1 处并关闭] TypeError: Cannot read properties of null (reading 'length')
        at refreshObserveEntry (js/engine.js:670:60)
```

**影响**：观察模式是 README 主推的核心玩法（"观察不是必须的，但它决定了你能看见多少条活路"），当前体验破碎且会报错。所有热点最终仍可拾取（引擎按旗帜计算"还剩几处"），但玩家必须反复进出观察模式。

**建议**：

```js
const remain = $$('#observe-layer .hotspot:not(.found)').length;  // 改成 $$ ，并按 0 情况处理
```

### P1-5　整段 `e7b` 剧情是死代码，`zhangwei_ok` 是孤儿旗标

**现象**：`js/story3.js:259` 的节点 `e7b`（张伟鼓起勇气抓住王珊珊往后拖，杨间趁机一拳打退鬼婴）**没有任何节点的 `next`、`route` 或选项指向它**，玩家永远看不到这段约 20 行的剧情，它授予的 `zhangwei_brave` 旗标也永远不会被设置。

**证据**：项目自带的 `tools/validate.js` 本身就报告 `不可达节点: e7b`；本次 `tests/structure.js` 与 `tests/suite_plot.js` 用"遍历所有跳转目标"的方式再次确认引用数为 0。

**推断的原始设计**：`js/data.js:592` 在 `p16` 观察「张伟」会给予 `zhangwei_ok` 旗标，但 `zhangwei_ok` **从未被任何条件读取**。`e6`（救人抉择）目前只有两个选项：「冲过去」→`e7`、「转身，跑。」→`e7r`。缺的显然是第三个以 `zhangwei_ok` 为条件的选项（如「张伟！拉她！」→`e7b`），这条内容与旗标因此一起被废置。

**建议**：在 `e6` 补上条件选项 `{ text:'“张伟！拉她！”', next:'e7b', when:{ flag:'zhangwei_ok' } }`。

### P2-6　线索档案跨局不会永久解锁（与 README 承诺矛盾）

**现象**：获得过的线索在**下一局游戏进行中**不会出现在档案里；只有回到标题画面（`state === null`）才看得到。

**根因**：`js/engine.js:888`

```js
const got = isClue ? (state ? state.clues.includes(item.id) : unlock.codex.includes(item.id))
                   : unlock.codex.includes(item.id);
```

线索页在游戏进行中只按**本局** `state.clues` 过滤，绕过了持久化的 `unlock.codex`；而「鬼物/人物/记忆」三页走的是 `unlock.codex`，是永久解锁的。

**证据**：预置 `unlock.codex = ['photo']` 后开新局，档案线索页显示"还没有记下任何东西。"；同一状态下鬼物页能正确显示上一局解锁的条目。

**与文档冲突**：README 第四节「档案：线索、鬼物、人物、记忆碎片。**看过的内容会永久解锁**」，第六节又写「结局、档案解锁、设定会单独保存，**不受"新游戏"影响**」。

**建议**：线索页改为 `state.clues.includes(id) || unlock.codex.includes(id)`。

### P2-7　HUD 时刻的 `deadline` 判定恒真，且没有对应样式

**现象**：`#stat-clock` 从开局第一秒（22:10）就带上 `deadline` 类。该类的本意是"临近/越过 05:30 死线时高亮提示"。

**根因**：`js/engine.js:792`

```js
const dead = s.clock >= toMinutes('05:30');   // 1330 >= 330 → 恒真
```

`clock` 是"当日分钟数"（22:10 = 1330），而 `05:30` 是次日凌晨（330）。22:10 到 24:00 的整个前半程恒 `>= 330`。

**补充发现**：`css/style.css` 中**根本不存在 `.deadline` 规则**，该 class 被切换但没有任何视觉效果——也就是说这个"死线提示"功能整体未实现。

**影响**：当前无可观察症状（因为无样式），但属于明确的逻辑错误 + 未完成功能。

**建议**：修正判定（例如按"距 05:30 剩余分钟数"计算并考虑跨日），并补上 `.deadline` 样式；若不需要该提示，则删除这段逻辑。

### P3-8　观察入口的「O」键提示从未渲染

`js/engine.js:573-583` 为观察入口对象定义了 `req: 'O'`，但 `renderChoices` 渲染提示时读的是 `c.hint`（`js/engine.js:604`）：

```js
req.textContent = ok ? (c.hint || '') : (c.lockedHint || '条件不足');
```

因此观察项的按键提示恒为空字符串。玩家虽然可以用 `O` 进入观察（README 有写），但界面上没有任何提示。**建议**：改读 `c.hint || c.req`。

### P3-9　`?auto=1` 冒烟模式进入观察模式后死锁

README 第九节把 `index.html?auto=1` 作为"自动随机通关，用于冒烟测试"的调试参数。实测该模式**必然在 `p2`（第一个带观察点的节点）卡死**：

`js/engine.js:975-988` 的 tick 只处理选项与 `advance()`，没有处理观察层。当随机点到「观察四周」进入观察模式后，`#choices` 为空、`advance()` 因 `advanceResolve` 为 null 而无效、而 `advance()` 又不像舞台点击那样被 `observeMode` 拦住——于是空转 2000 步后 `clearInterval`，**既不报错也不生成 `#auto-report` 报告**。

**证据**：

```
i=0  state=p2 ending=false timers=0 choices=0 text="刑警？"     ← 之后一直停在这里
最终: 无报告 | node= p2 | ending= false
```

**建议**：在 tick 中加入观察层处理（复用 `?obs=1` 的思路，或点击 `#observe-exit`），并让"未抵达结局"的情况也输出报告。

### P3-10　立绘资源未被使用 + 一处立绘路径不存在
