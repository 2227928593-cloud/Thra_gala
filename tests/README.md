# tests/ — 测试资产（本次测试新增，不修改任何生产代码）

被测对象是仓库根目录的 `index.html` / `js/` / `css/` / `art/`，**全部保持原样**。

## 运行

```bash
node tests/run.js            # 全部（核心 74 项 + 剧情 24 项 + 结构检查）
node tests/run.js core       # 仅核心功能套件
node tests/run.js plot       # 仅剧情可达性套件
node tests/prove_eighth.js   # 「第八个人」结局不可达的穷举证明
node tests/structure.js      # 静态结构检查
node tests/flags_usage.js    # 旗标/道具的"设置 vs 读取"对照（参考信息）
```

无任何外部依赖，仅需 Node.js（开发时使用 v24）。

## 方法：为什么不用浏览器自动化

理想方案是真浏览器驱动。但本沙箱会终止 Node `spawn` 出来的浏览器进程（退出码 `0x80000003`），
PowerShell 启动的 headless 实例其 CDP 端口也不稳定（`tests/cdp.js` 保留了可用的 CDP 客户端，供放开的环境使用）。

因此采用**真实引擎 + 最小 DOM**：在 Node 里实现一个够用的 DOM，把**真实的 `index.html` 与全部 `js/*.js`**
装进 `vm` 上下文运行，驱动的是生产代码本身，而不是重写的逻辑模型。

两个关键设计：

1. **虚拟时钟**（`harness.js`）。引擎的转场、打字机、幕卡全部依赖 `setTimeout`。这里把它换成
   可控的虚拟时间队列，测试可以毫秒级跑完整局游戏；`drainFor(ms)` 还能"只推进 N 毫秒"，
   用来观察 toast 这类会被定时器自动清理的瞬时 UI。
   > `pump()` 在队列为空时会多让出几轮事件循环：promise 链可能尚未执行到"安排下一个定时器"，
   > 否则测试会偶发失败（这个问题在开发中被真实踩到并修复）。

2. **已知缺陷标记**（`tf.js` 的 `testKnown`）。对于确认存在的缺陷，用例断言的是**期望的正确行为**，
   因此它会失败；`testKnown` 把失败登记为"已复现"而不计入通过数。
   这样缺陷一旦被修复，用例会自动转为通过，不需要改测试。

## 文件

| 文件 | 作用 |
|---|---|
| `dom.js` | 最小 DOM：选择器引擎（含 `:not` / `[attr]` / 后代组合）、`classList`、`dataset`、**`hidden` 等属性的反映**、`innerHTML` 解析、事件冒泡、`closest` |
| `harness.js` | 夹具：加载真实页面与脚本、虚拟时钟、`playthrough()` 驱动、观察模式兜底清理 |
| `tf.js` | 断言与汇总框架（含"已知缺陷"机制） |
| `structure.js` | 静态结构检查：重复节点 id、剧情图环、非法字段、资源引用与立绘使用率、条件/效果字段白名单 |
| `suite_core.js` | 核心功能 74 项：标题菜单 / 开局 HUD / 打字机与行内样式 / 选项 / 观察模式 / 档案解锁 / 存读档 / 键盘 / 设定 / 音频 / 边界健壮性 |
| `suite_plot.js` | 剧情 24 项：6 个结局实际通关、结局界面与回廊、120 次随机通关压力测试、档案与线索可获得性、关键分支互斥、死代码检测 |
| `prove_eighth.js` | 对 `e7r` 之后的子图做穷举（1099 状态），证明 `g7` / `end_eighth` 不可达 |
| `flags_usage.js` | 对照"被设置的旗标"与"被读取的旗标"，发现接线断掉的分支 |
| `cdp.js` | 零依赖 CDP 客户端 + 静态文件服务器（本沙箱不可用，保留备查） |
| `run.js` | 入口 |

## 已知会失败的用例

`tests/run.js` 全量运行的结果是 **98 项：通过 88，失败 10**。
这 10 项失败**全部**是已知缺陷，逐条说明见根目录的 [TEST_REPORT.md](../TEST_REPORT.md)；
`run.js` 末尾会把它们汇总为"已复现"清单，便于对照。
